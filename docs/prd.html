01 Three hard constraints

Read these before anything else. They shape every decision downstream.

Constraint 01

Nothing on Dhan trades 24×7

MCX GOLD is the longest session on the platform: 09:00–23:30 IST, Mon–Fri (23:55 in the US winter DST window), shut on weekends. That is ~14.5 hours a day against 6.25 for the equity chips. GOLD takes the "long session" slot, and the UI carries an explicit market closed, showing last snapshot state instead of pretending.

Constraint 02

"Live" means 3 seconds

Dhan rate limits the option chain to one unique request every 3 seconds per underlying and expiry — their own stated reason is that OI updates slowly. So OI, volume, IV and greeks refresh on a 3000 ms cadence. Only the underlying spot is genuinely tick-live, over the WebSocket feed. The screen shows two different freshness signals, never one blended lie.

Constraint 03

The token cannot sit in the browser

Dhan needs access-token and client-id headers, ties operations to whitelisted IPs, and serves no CORS for browser origins. v1 therefore ships a thin local Node backend. It is the only safe home for a live-account bearer credential — and it lets one poller own the 3 s budget instead of every open tab racing it.

Formatting, locked: under 1,000 raw · under 1e5 → K · under 1e7 → L · 1e7 and above → Cr; two decimals with trailing zeros stripped, which reproduces 51.09 K, 2.98 L and 16 Cr from your screenshot exactly. Any percentage whose denominator is zero or missing renders as an em dash — never NaN, Infinity or a misleading 0%.

06 Architecture

One poller owns the rate limit. The browser never sees the token.

browser (React 18 + TS + Vite)        local backend (Node 20 + Fastify)          Dhan
──────────────────────────────        ─────────────────────────────────         ─────────────────
OptionChainGrid   <── SSE ──  ChainPoller     one timer per key   ──>  POST /v2/optionchain
HeaderStrip                           DeriveEngine    section 04 rules             1 req / 3 s
LatencyPanel      <── SSE ──  TelemetryBus    ring buffer 500
InstrumentChips   ── REST ──>  /api/instruments  /api/expiries      ──>  POST /v2/optionchain/expirylist
SpotTicker        <── SSE ──  FeedClient      one WS, 6 symbols   ──>  wss://api-feed.dhan.co
                                      InstrumentMaster  CSV cache 08:00   ──>  images.dhan.co CSV
  • One ChainPoller per active key. Switching chips pauses the old poller after a 30 s grace period instead of killing it, so toggling back is instant.
  • Scheduled from completion, not from dispatch. A slow response can never stack two requests in flight and trip DH-904.
  • Backoff: 3 s → 6 s → 12 s → 30 s cap, reset on the first success.
  • Raw values survive. The backend ships the raw Dhan node alongside the derived block, so the panel can always prove what came from Dhan and what we computed.
  • Boring stack on purpose: Fastify, undici with per-stage timing hooks, ws. No UI kit, no chart library, no state library. Sparklines and the waterfall are hand-drawn SVG; 100 rows of CSS grid need no virtualisation.

07 Latency panel

Eight timestamps per call, and one honest asterisk.

You asked to see when the request goes to Dhan, when the response lands, and the gap between them. The panel does that, and then answers the question that follows it — whose fault is the gap.

StampBoundaryClock
queuedpoller decides to firebackend
dispatchedsocket write beginsbackend, via undici diagnostics
ttfbfirst response bytebackend
downloadedlast response bytebackend
parsedJSON parsed, section 04 derivations donebackend
pushedSSE frame writtenbackend
receivedSSE frame arrivesbrowser
paintedgrid committed, read in the rAF after React's commitbrowser

Headline number is round_trip = downloaded − dispatched, with end_to_end = painted − queued beside it. Server, download, compute and render are each derived inside a single clock domain. The one cross-clock value, transport, is labelled as an estimate in the panel itself — hiding that in a doc would be dishonest at exactly the moment the user is trusting the numbers.

Panel contents: three live numbers at 26px tabular; the stage waterfall for the most recent call; a 60-call sparkline with p50 and p95 reference lines; a p50/p90/p99/max row with success rate; a 3-second budget ring that fills between calls and turns amber the moment a response lands after its next slot was due; a 20-row call log that expands to the full stage table; an error ribbon carrying the Dhan code, a plain-language reading of it and the live backoff; and CSV/JSON export of all 500 buffered samples.

Thresholds are set on our own code, since Dhan's round trip is not ours to control: compute at most 15 ms for a 100-strike chain, render at most 50 ms, and total overhead outside the round trip at most 80 ms. If our overhead ever exceeds Dhan's, the panel says so in words rather than leaving you to read it off a bar.

Density first. Colour only where it carries meaning.

  • Column order mirrors your screenshot exactly — Vega, Theta, Gamma, Delta, OI, OI Chg, Volume, Vol Chg%, IV, LTP Chg, LTP, then STRIKE, then the mirror. Muscle memory transfers on day one.
  • Strike column sticks horizontally, header row sticks vertically. Row height 30px, data at 12px IBM Plex Mono with tabular figures.
  • ITM tint, not borders — strikes below spot tinted on the CE side, above spot on the PE side, at 60% of bg/inset.
  • Spot marker is a 2px dashed accent line drawn between the two strikes that bracket spot, with the live price in a pill on the strike column. The ATM row carries a 3px accent stripe.
  • One heatmap only: a 12%-opacity bar behind each OI number, scaled to the largest OI on that side. Everything else stays quiet so the bar means something.
  • Signed values keep their sign. Colour never carries meaning alone.
  • Changed cells flash for 400 ms — opacity only under prefers-reduced-motion.
  • Keyboard: ↑↓ row, ←→ column group, Home jumps to ATM, 1–6 switch instrument, E expiry, L panel, / search.

09 Design tokens

Instrument panel: cool blue-grey neutrals, one brass accent, semantics kept separate.

Brass reads as a dial marking rather than a brand colour, and it ties the palette to the GOLD chip. Because the accent is warm and the semantics are red/green, colour never has to do two jobs at once. Type is Archivo for structure, Newsreader for prose, IBM Plex Mono for every digit on screen.

Accessibility floor, non-negotiable: body text at 4.5:1 and borders at 3:1 in both themes, every control keyboard reachable with a visible 2px ring at 2px offset, 44×44 minimum touch targets on chips and buttons, and a real <label> on every input.

10 Acceptance

Binary, testable, no adjectives. v1 is done when every box is checked.

Data

  • Grid row count equals Object.keys(oc).length for every instrument
  • All 12 columns render on both sides at the decimals in section 04
  • ATM IV matches (ce.iv + pe.iv)/2 at the nearest strike to 2 dp against a fixture
  • PCR matches sum(pe.oi)/sum(ce.oi) over the full response to 2 dp
  • NIFTY market lot reads 65 from the instrument master, not a constant
  • Zero denominators render an em dash — no NaN, Infinity or 0% anywhere

Instruments

  • All six chips load an expiry list and a chain, or are disabled with a stated reason
  • Cached chip switch paints in ≤ 400 ms; uncached shows a skeleton
  • GOLD polls 09:00–23:30 IST on weekdays and shows the closed state outside it

Latency

  • Every call appears in the log with all eight stage timestamps
  • The three live numbers tick every 250 ms without re-rendering the grid
  • p50/p90/p99 match hand computation over the exported CSV of the same window
  • Zero sub-3000 ms repeats for one key across a 10-minute log
  • A forced DH-904 produces the amber chip and the 3/6/12/30 s backoff

UI & security

  • Twelve screenshots captured: every state, dark mode, 1024px, panel collapsed
  • Zero layout shift when data replaces the skeleton (CLS = 0)
  • Contrast verified at 4.5:1 body and 3:1 borders in both themes
  • Full keyboard operation without a mouse
  • Built browser bundle contains no credential string (grepped in CI)
  • .env git-ignored; .env.example carries key names only

11 Phases

One phase per session, roughly six to eight files each.

P0

Spike & skeleton

SPIKE-01 resolves the GOLD underlying. Instrument master downloader and cache, .env wiring, Fastify boots, /api/health returns all six resolved instruments with lot sizes.

Done when all six chips resolve to a real (scrip, seg, lot) triple — or GOLD is documented as blocked.

P1

Chain pipeline

ChainPoller on the completion-scheduled 3000 ms cadence, DeriveEngine implementing section 04, TelemetryBus, SSE endpoints, DH-901 and DH-904 handling.

Done when a 10-minute log shows zero sub-3000 ms repeats and derived ATM IV / PCR match a fixture to 2 dp.

P2

Option chain grid

Tokens as CSS custom properties, the grid, header strip, chip rail, expiry select, spot marker, ITM tint, OI bar, update flash.

Done when the screenshot matches the reference density and row count equals the response strike count.

P3

Latency panel

Three live numbers, stage waterfall, sparkline with p50/p95, percentile row, rate-limit ring, 20-row call log, CSV/JSON export.

Done when exported percentiles match hand computation and the panel updates without re-rendering the grid.

P4

States & polish

All eight component states, expressive error/empty/closed states, keyboard map, both themes, contrast audit, 1024px degrade.

Done when the twelve screenshots are captured and reviewed.
